## 3. The next stage: implement ADR-0032 (accepted, unimplemented)

Read `docs/decisions/0032-adjusted-read-basis-for-vendor-sourced-slices.md` in full before
touching code. Decisions 1-9 are the contract; the seams are:

- `core/availability.py`: a second, total-by-construction proof model beside
  `ActionCoverageProof` (`vendor_events_no_clock`), a `coverage_basis` field, and
  `ACTION_COVERAGE_SCHEMA_VERSION` 2 → 3. The strict model keeps its mandatory clocks —
  do not relax it and do not make its fields optional.
- `storage/lake_reader.py`: `with_price_adjustment(..., coverage_basis=...)`, **default
  `source_clock`**, so no existing call site changes behaviour until it opts in. One read admits
  one basis: mixing bases, or real rows against the demo lake's `synthetic_demo_seed` proof,
  must refuse.
- Stamps travel in data (coverage rows, feature rows and the feature schema version), never
  inferred from nulls or status strings. `data/catalog.jsonl` and any feature-schema version
  change only if decision 9 says so — regenerate with `uv run equity catalog-generate`, never
  by hand.

What must **not** change: the strict basis stays default; point-in-time research stays refused
(`validate_action_coverage_for_decision`, the `features/engineering.py` per-session visibility
check, the `ml/*` loaders); no clock is synthesized from ingestion time or ex-date; origin stays
`unknown` (ADR-0027); the demo lake's behaviour is unchanged; and the real root's Gold table may
only appear from an **explicitly opted-in run with its own authorization** (ADR-0030 d10).

Proof obligations (decision 8): a changed basis refuses a strict consumer; a mixed-basis read
refuses; the strict path's existing refusals still fire; a demo-lake read is byte-identical to
today; mutation proofs for each new refusal; and the reciprocal verification shape used on the
landed rows (re-adjusted output reproduces vendor OHLC/volume).

## 5. Traps that cost time here

- **The landing window is bounded by evidence, not by today.** The Part I refusals require each
  ticker's action watermark to reach its price rows, so the honest end is `min(watermarks)` —
  2026-08-20 (MSFT). Landing past it refuses four of five tickers. If you want a later window,
  refresh actions first and re-read the watermarks.
- **A transient vendor row is not a transform bug.** 2022-07-22 was refused by the pointblank
  quality gate (one row failing `> 0`); a re-fetch was clean and the same date landed on retry.
  Diagnose before "fixing" the reconstruction.
- **Both orchestrator branches matter.** The serial branch (the backfill path) once dropped
  `lake_dir`, sending real-root writes into the canonical lake. Anything threaded into
  `_finalize_market` must reach both branches.
- **yfinance supplies no MIC/exchange**, so identity comes from the exact current
  `TickerConfig`; a fetcher without one raises `LegacyIdentityUnavailableError`. Both `ingest`
  and `backfill` now pass it. An unconfigured ticker still fails closed — keep it that way.
- **Test doubles must model the real object.** A `SimpleNamespace` monitor without
  `check_status`/`check_notes` broke four CLI tests; a byte-identical restore candidate
  short-circuits before the space pre-check and made a test vacuous.
- **Clean up what you create.** `VACUUM INTO` left the rebuilt file on disk until the swap path
  unlinked it — the test caught it, not review.
- **A `not_applicable` is not a PASS.** Reporting an unevaluable check as PASS claims verified
  health; the monitor's canonical report is pinned unchanged by test.
- **Never publish or commit private material**: the ledger, real-slice rows, absolute paths,
  `.env` values, digests-as-identifiers (see the H00 review's B1-B10).
- **Never run `--apply` against a real ledger, a wide ingest, or a feature run without an
  explicit instruction.** Report-only is the default for a reason; `data/portfolio/` does not
  exist in this checkout.
- Reviewer per stage with a formal verdict (`PASS` / `NEEDS-REVISION` / `BLOCKED`); never record
  a verdict you did not receive. Acceptance of a policy ADR is **not** authorization to run it.
