# ML Rigor User Guide

## Overview

The `equity ml` command group runs the Phase 2A "ML rigor" harness — the
machine-learning comparisons and ablations that materialize the three ML
[FindingCards](../developer/architecture/ARCHITECTURE.md) under `data/findings/`:

| Command | Card(s) written | Axis |
|---|---|---|
| `equity ml compare` | `meta-label-vs-direction`, `xgb-vs-lgbm` | labeling, model |
| `equity ml ablate`  | `enrichment-ablation` | ablation |
| `equity ml train`   | _(none — trains one model)_ | — |

Each harness is **per-ticker**: walk-forward folds are derived from a single
feature time series. The card's `scope` records the ticker(s), window sizes, and
backends so a verdict is honest and reproducible.

## Prerequisite: feature history backfill

`ml compare` and `ml ablate` read pre-computed features from
`03_gold/features`. If that history is empty the commands exit non-zero and point
at the backfill command rather than auto-backfilling (AGENTS.md guardrail):

```bash
# Demo subset (first 6 liquid US tickers)
dotenvx run -- uv run equity pipeline --markets us \
    --tickers AAPL,MSFT,GOOGL,AMZN,META,NVDA --allow-history-backfill
```

Confirm `data/lake/03_gold/features/` is populated before proceeding. Missing
feature history requires `--allow-history-backfill` with scoped markets and
tickers.

## `equity ml compare` — labeling + backend comparison

Runs two comparisons on the same per-ticker feature frame and writes two cards:

```bash
dotenvx run -- uv run equity ml compare --universe demo
# -> meta-label-vs-direction.json, xgb-vs-lgbm.json
```

- **`meta-label-vs-direction`** — does v2 meta-labeling (triple-barrier) beat v1
  raw next-day direction on out-of-sample precision?
- **`xgb-vs-lgbm`** — XGBoost vs LightGBM on OOS accuracy, Brier score, and
  feature-importance agreement (Spearman rank correlation).

## `equity ml ablate` — feature-enrichment ablation

Scores enriched features (macro / sentiment / SEC / analyst) against a
technical-only feature set over the **same** walk-forward folds:

```bash
dotenvx run -- uv run equity ml ablate --universe demo
# -> enrichment-ablation.json
```

The technical-only arm is regenerated upstream with `include_macro=False`. The
two arms carry different feature columns, so cross-scoring one arm's model
against the other's frame would trip the warn-only feature-skew guard (D12). The
harness scores each arm on its own columns and records `feature_skew_warn_only:
true` in the card scope.

## `equity ml train` — single model training

The canonical model-training entrypoint: trains one backend classifier and
writes a model artifact, surfacing `--backend`. (`equity forecast --mode train`
is the flat command wrapping the same trainer; it does not expose `--backend`.)

```bash
dotenvx run -- uv run equity ml train --ticker AAPL --backend lightgbm --model-mode v2_meta_label
```

| Flag | Values | Notes |
|---|---|---|
| `--ticker` / `-t` | any symbol | Optional; defaults to the first ticker of the universe. |
| `--backend` | `xgboost` \| `lightgbm` | Default `xgboost`. |
| `--model-mode` | `v1_direction` \| `v2_meta_label` | v1 = raw direction, v2 = triple-barrier meta-label. |
| `--tune` | flag | Hyperparameter tuning via `GridSearchCV`. |
| `--start` / `--end` | `YYYY-MM-DD` | Default ~1 year lookback to today. |

## Common flags

`equity ml compare` and `equity ml ablate` share these options:

| Flag | Default | Notes |
|---|---|---|
| `--universe` | `demo` | Config ticker group in `config/tickers.yaml`. |
| `--ticker` / `-t` | _(first of universe)_ | `--universe demo` runs **AAPL**; override with `--ticker MSFT`. |
| `--start` / `--end` | `YYYY-MM-DD` | Default ~2-year lookback to today. |
| `--output-dir` / `-o` | `data/findings` | Findings directory. |
| `--train-window` | `252` | Walk-forward train window (rows). |
| `--test-window` | `21` | Walk-forward test window (rows). |
| `--embargo-window` | `1` | Post-test embargo (rows). |
| `--verbose` / `-v` | flag | Debug logging. |

## Outputs

- **FindingCards** — JSON files under `data/findings/`
  (`meta-label-vs-direction.json`, `xgb-vs-lgbm.json`, `enrichment-ablation.json`).
  Reload them with `load_finding_cards`. Each card carries `verdict`
  (`positive` / `negative` / `inconclusive`), a one-line `conclusion`, numeric
  `metrics`, and a `scope` block (tickers, windows, backends) for reproducibility.
- **Weights & Biases** — if `WANDB_API_KEY` is set, each comparison logs a run and
  one Report per comparison (best-effort, never a hard dependency). If logging
  fails the local cards are still written.

## Reading the verdicts honestly

The default `--universe demo` runs a **single** ticker (AAPL). Single-ticker
out-of-sample results on short windows can flip a verdict — that is expected.
For a defensible verdict:

- Run across more of the universe with `--ticker` (one card per ticker, then
  compare the `scope.tickers`-scoped conclusions), **or**
- treat each card as explicitly per-ticker — the `tickers` field in `scope` is
  the contract that keeps a single-ticker verdict honest.

Negative and inconclusive results are valid and encouraged; record them as-is.
