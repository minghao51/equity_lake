# Read API (Phase 2B)

A read-only FastAPI service over the equity data lake. It exposes the research
artifacts (FindingCards), signal history, trained models, predictions, and
backtest reports as JSON over HTTP — turning the lake into a queryable service.

## Run locally

```bash
uv run equity api serve                  # http://127.0.0.1:8000
uv run equity api serve --port 8080      # custom port
uv run equity api serve --reload         # auto-reload (development)
```

OpenAPI docs are served at `/docs`; a liveness probe lives at `GET /health`.

> **Non-loopback hosts are protected by default.** The API (including `/docs`)
> has no authentication. Binding `--host 0.0.0.0` or another non-loopback
> address warns and requires interactive confirmation; a refusal or EOF aborts
> startup. For an explicitly authorized noninteractive deployment, pass
> `--allow-unauthenticated-exposure`. The warning remains, and the operator is
> responsible for a trusted network boundary or an authenticated reverse proxy.
> This flag does not add API authentication.

## Endpoints

| Method | Path | Description |
|---|---|---|
| `GET` | `/health` | Liveness probe → `{"status": "ok"}`. |
| `GET` | `/findings` | All serialized FindingCards under `data/findings/`. |
| `GET` | `/findings/{id}` | One FindingCard by id (404 if absent). |
| `GET` | `/signals?target_date=YYYY-MM-DD` | Buy/sell/hold signals for a date (default: last completed trading day, market-calendar-aware). |
| `GET` | `/models` | Trained-model summaries (backend, mode, fold metrics). |
| `GET` | `/predictions?target_date=&market=&mic=&symbol=&ticker=&limit=` | Raw Platinum prediction history, newest-first, with additive per-row status fields and read-coverage headers. |
| `GET` | `/backtests` | Arena/backtest run reports (strategy × cost-regime metrics). |

### Predictions read contract

Without `target_date`, `/predictions` reads the inclusive 31-calendar-day
window ending on the current **UTC calendar date** (start = UTC today − 30
days). An explicit `target_date=YYYY-MM-DD` selects exactly that date, including
history older than the default window. `limit` remains 1–1000 and caps returned
rows; it does not short-circuit the scoped scan.

`market`, `mic`, and `symbol` are explicit identity filters. Market accepts a
canonical market or its supported short alias, and market/MIC combinations are
validated. MIC is never inferred. Legacy `ticker` remains a broad alias and may
match the same symbol at multiple venues; combine it with market/MIC to narrow
the result. If both `ticker` and `symbol` are supplied, they must agree.

The response body remains a JSON list, including for a genuinely empty result.
Coverage headers are present on both nonempty and empty successful responses:
`X-Predictions-Window-Start`, `X-Predictions-Window-End`,
`X-Predictions-Snapshot-Version`, `X-Predictions-Scan-Status`,
`X-Predictions-Processed-Rows`, `X-Predictions-Returned-Rows`,
`X-Predictions-Selected-Files`, `X-Predictions-Selected-File-Bytes`, and
`X-Predictions-Decoded-Bytes`. They identify the UTC/date query window and the
single pinned Delta snapshot used for that request.

Every returned historical row keeps its stored fields and gains `api_*` status
fields. Identity is classified as structurally `valid`, `unknown`, or `invalid`;
feature schema as `current`, `historical`, `unknown`, or `invalid`; and stored
date/direction/probability as `valid`, `unknown`, or `invalid` (probability
must be numeric, finite, and in [0, 1]). Non-finite numeric values remain
visible as JSON strings (`NaN`, `Infinity`, or `-Infinity`) and carry invalid
status rather than breaking JSON serialization. These checks do not prove model
origin.
The writer currently does not persist a supported row-bound forecast proof, so
`api_provenance_status` remains `unknown` and rows are marked
`api_usability_status=not_current_usable`, even when identity, schema, and
values are structurally valid. A model-version string, current schema number,
filename, or current configuration is not provenance. Historical/legacy rows
remain visible with explicit reasons; they are not silently discarded or
qualified. `api_prediction_semantics_status` is also unknown; in particular,
a stored `v2_meta_label` mode can encode a binary meta-label that the writer
maps to `up`/`down`, which does not establish directional prediction semantics.

The scan pins one Delta version, applies date partition selection and Arrow
identity/ticker filters before converting rows to Python, and sorts by date,
composite identity, then a stable row-payload tie-breaker before applying the
return limit. Fail-closed read budgets are: 4,096 selected files; 256 MiB total
selected Parquet-file bytes; 50,000 Arrow-filtered processed rows; and 64 MiB
of decoded Arrow batches, using batches of at most 256 rows. File bytes are the
full local Parquet sizes in the date-selected partitions; processed rows and
decoded bytes describe batches emitted after Arrow filters. A batch can cross
the row/decoded-byte threshold before exhaustion is detected. Exceeding a
budget returns HTTP **503** with `detail` identifying the budget and
`X-Predictions-Scan-Status: budget_exceeded` plus the available window/snapshot
counters; no truncated list is returned. These supported Delta APIs eagerly
load the transaction snapshot and enumerate the date-selected file URI list
before the file-count check, so the budgets do not claim a hard cap on
transaction-log/snapshot metadata memory. The endpoint does not materialize a
full Arrow table or claim a hard bound on Delta-log metadata.

Missing/corrupt/unpartitioned Delta tables surface as HTTP **503** with an
`unreadable` detail. Invalid query values or inconsistent identity filters
remain HTTP **422**. A readable query with no matching rows remains HTTP **200**
with `[]` and its coverage headers.

## Docker

The Dockerfile `api` stage defaults to a loopback bind inside the container.
To reach it through a host port, explicitly opt into the unauthenticated
container bind while publishing only on host loopback:

```bash
docker build --target api -t equity-lake-api .
docker run -p 127.0.0.1:8000:8000 -v "$(pwd)/data:/app/data" equity-lake-api \
  equity api serve --host 0.0.0.0 --port 8000 --allow-unauthenticated-exposure
```

Do not use a wildcard host-port mapping such as `-p 8000:8000` unless public
network exposure is intentional and separately protected. The container bind
is unauthenticated even when the host port is restricted to loopback.

## Design notes

- **Read-only.** No endpoint mutates the lake; every router wraps an existing
  reader (`load_finding_cards`, `load_signals`, `read_delta`, or a filesystem
  listing).
- **Boundary-enforced.** `src/equity_lake/api/` may depend only on `core`,
  `storage`, and `findings` — never `cli` or `pipeline` — enforced by
  `tests/unit/test_import_boundaries.py`.
- **Lazy FastAPI.** `import equity_lake.api` does not import FastAPI; the
  framework loads only when `create_app()` runs (or `equity api serve`).
